# 写入、证据和撤销规则

## 统一入口

ProjectService 负责资料、状态、revision、updatedAt 与总进度；SurveyService 负责答案、备忘、追问。界面只通过这些服务提交变化，不直接绑定持久化模型字段。ModelContext 主线程共享以保持 MCP 与界面可见性。

现场逐字输入允许草稿（例如还未输入完的数字、“其他”说明），状态由 AnswerValidator 决定；MCP 批量导入拒绝非空但不合法的答案。两者共享归档保护、题型判定、修订和进度规则。忽略/转移不因追加笔记自动解除。

完成状态需要所有必答题有效；归档只允许明确恢复到进行中，或在必答题齐全时恢复为已完成。编辑使必答答案失效时，已完成项目自动回到进行中。

项目/部门/报告总题数包含基础题与已采纳追问；进度不是只统计必答题。用户保存失败会看到错误，保存事务回滚；AI 润色返回后再次校验单题修订和归档状态。

## 证据与报告

答案 evidence 保存来源原文或访谈定位，list_questions 回读；与 otherText、笔记、转写、润色一起进入撤销快照。证据本身不作为完成答案。当前 evidence 是字符串，不是附件或录音存储系统。

报告包含有效答案及所选内容开关允许的现场记录；无效、忽略、转移分别标注，不冒充已确认回答。未完成题目单独列为缺口；“其他”显示说明而非 __other__，保留选择题额外文本。Word 使用与 Markdown 相同的快照。

## 幂等和撤销

新请求使用新 request_id，网络重试复用同一个 ID 和同一请求内容。相同工具、不同内容或项目不能复用 ID（IDEMPOTENCY_CONFLICT）；request_id 被省略的兼容调用不提供变更集去重保证。

撤销只支持答案/转写批次，先逐题比较写入后的快照、记录 ID 和单调递增的单题 revision。任何目标题有后续改动（即使改回原值）都返回 UNDO_CONFLICT，不部分撤销；其他题或项目资料变动不阻挡本批撤销。归档项目禁止撤销。

旧变更集没有请求指纹或单题修订号，无法证明可安全重放/撤销，会明确拒绝；历史项目、答案、备忘、追问和变更记录仍保留。需要调整旧内容时，回读后发起新的明确修改，不把旧 request_id 用于新操作。
